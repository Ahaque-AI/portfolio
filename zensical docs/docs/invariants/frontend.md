# Frontend rules

- Use Astro static output and the shared design in the root `DESIGN.md`.
- Keep portfolio content and legal pages available without JavaScript.
- Use native HTML/CSS and small scripts first. Add React only for an interaction
  whose state or complexity justifies it.
- Give each step one primary action without hiding alternatives, back, navigation,
  privacy information, or accessible alternatives.
- Require full name on both continuation paths. Full introduction also needs
  email and agreement; name-only continuation needs neither. Policy pages stay open.
- Do not use browser controls or browser automation. The owner performs manual
  visual and interaction tests. Run type checks, builds, and focused non-browser
  tests; report manual checks as unverified rather than claiming they passed.
- Apply the environment's relevant design skills during UI work; keep visual
  decisions in a shared design document when that work begins.
